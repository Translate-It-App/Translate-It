# Firefox page-translation capability probe

Run with `pnpm exec node scripts/dev/page-translation-e2e-firefox/run.mjs`; focused tests use `pnpm test:run scripts/dev/page-translation-e2e-firefox.test.js`. The probe re-execs itself in a rootless network namespace and verifies exactly loopback-only addressing with no IPv4 or IPv6 routes before running Firefox or reading browser version. It uses Firefox's announced WebDriver BiDi websocket directly; no geckodriver or automation framework is involved.

The probe subscribes to BiDi request events before registering interception. It continues only loopback fixture traffic and the exact runtime-collector `POST`, provides the known empty startup voice list, fails every other intercepted HTTP(S) request, then closes request admission and drains handlers before teardown. A fresh authenticated runtime bridge binds an inert page in the driver-created tab before extension installation, verifies the instrumented background startup, then navigates that same tab to the fixture and verifies the real content startup/readiness reports and acknowledgment. The bridge proof is separate from BiDi realm inspection: it does not promote `backgroundInspection` or `contentInspection`, and does not bypass gates for native background/content negative-fetch probes. No Firefox extension system-access override is enabled; installation metadata is not treated as execution readiness.

The runtime authentication token is generated independently per run, used only for the loopback fixture and private worker build configuration, and redacted recursively from BiDi events, command journals, errors, and artifacts. Bridge reports are validated for exact sequence, source entry, sender/tab/frame/URL/navigation identity, readiness checks, and sliced-discovery flags. Real Edge request-body/response handling and the held-request abort/settlement/stale-delivery lifecycle are explicitly **not implemented** in this bounded probe; those capabilities remain `NOT_TESTED` even when bridge readiness succeeds. Background/content negative fetches are attempted only when both actual BiDi realms, readiness, and exact discovery flags pass. The probe does not claim that deferred scenarios run automatically when a gate becomes available.

An atomic JSON artifact is written to `/tmp/opencode/page-translation-firefox-<run-id>.json` by default. Set `FIREFOX_PROBE_ARTIFACT` to choose its path (the parent directory must already exist). If that path already exists, a run-ID-suffixed path is used so prior artifact bytes are preserved. Results use `SUPPORTED`, `UNSUPPORTED`, `FAILED`, and `NOT_TESTED`. Exit status: 0 only when every required capability is `SUPPORTED`; 2 when a capability is unsupported or gated/not tested; 1 for failure, timeout, protocol, cleanup, or artifact errors. Artifacts include a unique run ID, HEAD and source hashes, runtime versions, commands/events/request outcomes, network-scope evidence, and limitations. This is a bounded capability probe, not the full Firefox E2E suite or 1000-target matrix.
