# Select Element live benchmark

Use a development build; production builds do not emit benchmark timing events. Build with `pnpm run dev:chrome` or `pnpm run dev:firefox`, then load the extension using the [development instructions](../../../../docs/guides/CONTRIBUTING.md#development).

First configure the extension with the provider credentials, source/target languages, and relevant Select Element extraction/settings; the benchmark does not change settings. Run `PORT=4179 node scripts/dev/select-element/live-benchmark/serve.mjs` and open the printed loopback URL with the extension enabled. Reuse the same fixed port (and URL origin) for baseline and candidate runs so browser localStorage persists. In **Trial Configuration**, choose a fixture, baseline/candidate label, and Warm-up/Warm/Cold trial type, click **Start trial**, activate Select Element normally, then click the fixture's border/padding rather than a paragraph. Each trial builds a fresh fixture before measurement and freezes controls until recorded. In **Trial Outcome**, report the outcome; leaving/reloading records incomplete.

Each selectable 300×300 px `<section>` root contains multiple independent `<p>` parents: 8, 50, or 300 logical parents/text nodes; Mixed HTML has 25 logical parents and 50 text nodes with meaningful `<strong>`/`<em>` inline formatting. Root area is 90,000 px², within ElementSelector's area heuristics. Click the root border/padding, not a paragraph, to select the full section. The control panel is outside the fixture and excluded. Keep settings and fixture constant; change only the build being compared.

Warm-up and Warm trials wait for the configured metadata snapshot before allowing selection; a bounded timeout records an incomplete trial and blocks retry until the outstanding read settles or the extension is reloaded. Cold trials defer this snapshot until after measurement so it cannot prewarm settings storage; its capture phase is recorded. An incomplete Cold trial with an accepted click and no terminal event skips metadata capture to avoid overlapping an operation still in progress. Configured metadata includes effective provider, applicable model, numeric optimization level (1–5), source/target languages, AI Context, AI Conversation History, Select Element Translation Font, and extension version. Adapter-resolved provider, target language, and extraction mode are stored separately from provider-confirmed execution values, which are explicitly unknown/not observed. Unavailable values remain unknown. The concise configuration heading and comparisons include settings/trial type but exclude extension version so builds remain comparable. Legacy records are preserved with unknown metadata and trial type. **Warm-up**, **Warm**, and **Cold** are independent trial types (Warm is default). Stored/exported records use schema version 4; export and clipboard share the same serializer. Events are loopback-only, opt-in, and tied to the current trial. Records contain only allowlisted safe scalar metadata, never credentials, URLs, prompts, request payloads, page text, or arbitrary settings objects. Timing is extension-observed and does not indicate physical provider completion.
